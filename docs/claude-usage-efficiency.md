# Claude 사용량 효율화 메모 (naver-news 프로젝트)

> 2026-08 기준, VS Code(Claude Code) + 브라우저 채팅 병행 작업 중 정리한 메모.
> 한도가 예전보다 빨리 차는 것 같다고 느껴질 때 다시 읽어볼 것.

## 왜 빨리 차는가

- **대화가 길어질수록 매 메시지가 비싸진다.** Claude는 매 턴마다 이전 대화 전체를
  다시 처리하기 때문에, 같은 질문이라도 대화 초반보다 후반이 훨씬 많은 토큰을 씀.
  → 주제가 바뀌는 시점마다 **새 대화창**을 여는 게 가장 효과가 큼.
- **VS Code(Claude Code)와 브라우저 채팅은 같은 사용량 풀을 공유.** 같은 작업을
  두 군데서 중복 검증하면 그만큼 두 배로 소모됨.

## 이 프로젝트에서 실제로 낭비였던 패턴

1. **"이미 반영된 줄 알았는데 실행이 안 됐던" 반복**
   VS Code에서 "완료했다"는 말만 보고 캡처를 가져왔다가, 알고 보니 커밋/푸시가
   안 됐거나 다른 세션에 묻힌 경우가 여러 번 있었음. 그때마다 리포지토리 전체를
   다시 pull해서 처음부터 재진단해야 했음.
2. **아이콘/배지 정렬을 픽셀 단위로 여러 라운드 왔다갔다**
   크기 조정 → 정렬 어긋남 → 모바일만 깨짐 → 숫자 배지 위로 쏠림... 식으로 조금씩
   나눠서 요청하다 보니 왕복이 늘어남.
3. **같은 파일/CSS 클래스를 여러 번 다시 조회**
   확인했던 내용을 다음 턴에 또 처음부터 grep해서 확인하는 비효율.

## 앞으로 줄이는 방법

- [ ] **주제 바뀌면 새 대화창** — 위젯 하나 작업 끝나면 새로 시작
- [ ] VS Code 완료 보고 받으면, 여기로 캡처 보내기 전에 **커밋 해시 + push 성공
      로그**가 실제로 찍혀있는지 먼저 확인 (없으면 "커밋/푸시 로그 보여줘"라고
      한 번 더 요구)
- [ ] 디자인/정렬류 미세조정 요청 시, 처음부터 프롬프트에
      **"Playwright로 스크린샷 찍어서 눈으로 맞을 때까지 반복 조정"** 포함
- [ ] 이미 여러 번 검증된 안정적인 기능(예: DART 1시간 크롤러)은 특별히 건드리지
      않았으면 매번 재확인하지 않기 — 의심되는 부분만 콕 집어서 질문
- [ ] 여러 개 고칠 게 있으면 하나씩 보내지 말고 **체크리스트로 모아서 한 번에**
- [ ] 급하지 않은 검증/디자인 다듬기는 **주간 한도 리셋 이후**로 미루기

## 사용량 화면 보는 법 (참고)

- **현재 세션**: 5시간 단위로 리셋. 지금 대화가 얼마나 무거운지의 지표.
- **주간 한도**: 매주 지정 요일 리셋(예: 목요일 21:59). 이게 꽉 차면 이후부터
  크레딧이 소진되기 시작함.
- **크레딧**: 주간 한도 다 찼을 때 API 표준 요금으로 과금되는 선불 잔액.
  평소엔 안 쓰이다가 한도 초과 시점에만 빠르게 줄어듦.
